# 服务器部署实战与 Obsidian 知识库接入

> 2026-08-25/26 的两件运维经验沉淀：① 把 project-kanban 部署到公司 Win11 服务器并接公网 `kanban.forestkopa.top`；② 把项目知识库 `docs/knowledge` 接入 Obsidian 软件并适配 LLM Wiki 技能。

## 一、服务器一键部署实战教训

- **方案**：拷贝文件夹 + 跑 `tools/deploy-server.ps1`（全 ASCII 防 PS5.1 编码坑；含备份 / 凭据迁移 / NSSM 幂等注册 / 验证 / 回滚）。
- **隧道**：Cloudflare Named Tunnel，凭据随包带 `tools/cloudflared/`，服务器零外部依赖。
- **NSSM 幂等注册**：`nssm stop/remove` 服务不存在时退出码非零会触发 `ErrorActionPreference=Stop` 中断 → 改 `cmd /c "nssm stop X 2>nul"` 包装，已修并入库（commit `bd22928`）。
- **同一 tunnel ID 多连接并存**：本机 + 服务器同时跑 cloudflared，公网流量随机分发 → 必须**蓝绿切换**（先停本机 `kanban-watchdog`，再服务器部署验证）。
- **公网区分 demo/正式**：`config.yml` 把域名转发到 `5180`(演示)，切正式改 `5181`（待办）。验证：`curl https://kanban.forestkopa.top/api/readonly` 看 `demo` 字段；本地 `5180`、公网走隧道。
- **打包双包机制**：`deploy.zip`（含 data/，仅首次）/ `update.zip`（不含 data/，后续更新，数据库永不覆盖），由 `tools/package.ps1` 固化。

## 二、Obsidian 知识库接入

- `docs/knowledge` 早有 `00-MOC` + `01~10` 原子笔记 + 双链 + `llms.txt`（历史会话沉淀，非本轮生成）。
- **本机装 Obsidian** → Open folder as vault 指向 `docs/knowledge/` → `.obsidian` 自动生成，双链/图谱/反向链接生效。
- **llms.txt 是开放索引标准**（llmstxt.org），非软件；给 AI 工具定位 vault，与 Obsidian 互不影响。
- **适配 obsidian-wiki 方法论**：建 `wiki-lint`（断链 / 孤儿 / 缺 frontmatter 体检）+ `wiki-update`（经验蒸馏进 vault）两个 WorkBuddy 用户级 skill，不装其 CLI、不套重型 vault 结构（index/log/hot/_raw/provenance）。
- `.gitignore` 加 `.obsidian/` 防本地配置误提交。
