# 大赛投递与工作台模板（单文件 HTML）

## 背景
项目投递腾讯职场「AI 工作台模板共创大赛」。「02 工作台模板链接」栏需提交一个**可访问的 HTML**（WorksBuddy 个人工作台投稿格式 = 单 HTML 网页、无需外部接口）。

## ⚠️ 方向纠偏（重要）
**早期做成"workbuddy.link 公开页 → 跳转 `kanban.forestkopa.top`（公网 5180 演示站）"的启动页是错误的方向。** 用户纠正：
- 不该指向公网演示站 `kanban.forestkopa.top`；
- 应基于**本机真实运行看板 localhost:5181** 来产出；
- 参赛"HTML 格式" = 把 kanban 做成**单文件独立 HTML 工作台模板**，不是外链跳转页。

> 参赛评测更关注「模板本身能不能直接用」——单文件 HTML 双击即开、无需服务器，正契合 WorkBuddy 工作台模板投稿格式（多个官方示例均强调"单HTML网页，无需外部接口"）。

## 正确产出
**文件：`kanban-workbench-template.html`（项目根目录，≈210KB，完全自含）。**
- ⚠️ **关键纠偏（2026-08-25）**：用户指出上一版是手搓近似代码（43KB，非最新）。现改为**真实最新代码**重建：
  - `build_template.py` 把真实 `public/index.html` + `public/style.css` + `public/app.js`（116KB，即 localhost:5181 真实前端）内联为单文件，并在 `<head>` 前置 `offline-adapter.js`。
  - `offline-adapter.js`：全局重写 `window.fetch`，拦截所有 `/api/*` 请求路由到浏览器内 localStorage 仓储；强制 `/readonly` 返回 `{demo:true}` 跳过登录；灌入 3 个示例项目（智能门锁 / 智能摄像头 迭代 v2 / 智能门铃 预研）+ 2 模板 + options；真实 `app.js` **零修改**。
  - 因此发布页运行的就是与本地一致的**真实看板前端**，仅数据层被离线垫片替换。
- 能力同真实 kanban：侧边栏项目列表 + 顶栏（搜索 / AI 助手 / 主题切换 / 导出）+ 视图切换（看板 / 甘特图 / 周报 / 全景 / 月报 / 报告 / 日历 共 7 视图）。
- 看板：拖拽改状态、增删改任务（标题/备注/起止/阶段/负责人/工期/里程碑），阶段色条着色。
- 甘特图：按任务起止渲染时间轴条、周末灰底、今日红线。
- 周报 / 月报：按本机日期动态生成本周完成 / 进行中 / 下周计划 / 风险预警。
- 报告：阶段完成度 + AI 项目总结（`/ai/summarize` 由适配器返回离线启发式文本；接 AI Key 可换大模型）。
- AI 助手：一句话描述 → `/ai/generate-tasks` 本地启发式拆解任务清单 → 一键创建项目。
- 其他：新建项目、浅/深色主题（持久化）、导出 JSON、打印/导出 PDF、搜索、按人汇总（/report）。
- 数据存 `localStorage`（key 前缀 `kb_offline_v1_`，如 `kb_offline_v1_projects`），内置示例项目，可 `window.__resetKanbanDemo()` 重置。

## 校验
- `node --check` 等价解析：内联 JS 语法 OK，单 `<script>`×2（适配器 + app.js）闭合，无 `http(s)`/`fetch` 到外部（仅 `window.fetch` 被适配器重写拦截 `/api`），无 `<link>` 外链 → 自含确认。
- jsdom 无头冒烟测试（`_smoke_v2.js`，最新真实前端）：init(3 项目 / 6 看板列 / 11 卡) + demo 徽标显示 + 7 视图切换零报错 + 甘特 187 节点 + 适配器 `/api/projects` 返回 3 项目 + **新增任务持久化（before=20 → after=21）**，全程零运行时报错 → `SMOKE_OK`。
- 修复记录：适配器初版在 task/project 的 PUT/DELETE/POST 处理中「改对象后 `saveProjects(projects())` 重新读 localStorage」导致改动丢失；已改为「捕获同一数组引用后保存」，新增任务现已持久化。
