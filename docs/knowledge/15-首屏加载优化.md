# 首屏加载优化（splash 遮罩 + 并行初始化请求）

## 现象
用户反馈「打开主页后要等一会儿才能加载完全部内容，体验不好」。

## 根因（两处）
1. **首屏白屏无反馈**：`loadAll()`（app.js）要等 4 个初始化请求**全部串行返回**才调一次 `render()`；`render()` 跑之前页面是空白的，用户先看到白页再等数据。
2. **请求串行 + 大体积**：4 个请求顺序 `await`（每个吃一次 RTT）；公网走 Cloudflare 隧道时延迟叠加更明显。实测 demo 库：`app.js` 140KB、`/api/projects`（含 tasks 全量）75KB、首屏 4 个串行请求。

## 改动
- `index.html`：`<body>` 开头加 `<div id="splash">`（纯 CSS spinner + 「看板加载中…」），**同步渲染**，JS 执行期间已可见，消除白屏。
- `style.css`：加 `#splash` 固定遮罩样式 + `.hide` 淡出过渡（`.sp` 旋转动画，适配主题变量 `var(--bg)/var(--text)`）。
- `app.js`：
  - `loadAll()` 内 4 个请求改 `Promise.all` 并行（`/options`、`/readonly` 用 `.catch(()=>null)` 兜底，不阻塞主流程）。
  - 新增 `hideSplash()`：`loadAll` 末尾（无论成功失败）给 `#splash` 加 `.hide`，400ms 后 `remove()`。

## 关键坑
- **`app.js <script>` 必须在 splash 之后**（index.html line 370，splash 在 line 15）。否则脚本执行时 `#splash` 尚未解析，`hideSplash` 拿不到元素 → splash 永远不消失。本仓库脚本在 `</body>` 前，安全。
- splash 仅可见性优化，**不减少实际数据量**；若真实服务器项目/任务远超 demo（8 项目/148 任务），board 首屏 DOM 渲染仍可能慢，splash 只盖住等待而非加速。

## 验证
- `node --check app.js` 通过；`Promise.all` 出现 1 次、`hideSplash` 2 次（定义+调用）。
- 开发机 5181 实时返回新 HTML（含 `id="splash"`）、新 CSS（含 `#splash`）、新 app.js（含 `Promise.all`）。
- 公网隧道场景并行收益最大（省 3×RTT）；本地 localhost 本就快，主要为消除白屏感知。
