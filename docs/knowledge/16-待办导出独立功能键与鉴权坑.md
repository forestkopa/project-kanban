# 待办导出独立功能键 + 鉴权坑

## 改动(v1.4.3 候选)
- **后端** `server.js:799-820` 接收 `kind: today|week|month` + `range:{mon,sun}`,按 kind 区分文件名:
  - today → `今日待办_YYYYMMDD.xlsx`
  - week  → `周报待办清单_YYYYMMDD.xlsx`(向后兼容)
  - month → `本月待办_YYYYMMDD.xlsx`
  其他逻辑不动;`buildTodoXlsx(projects, monIso, sunIso)` 仍按 mon~sun 范围二次过滤,前端预过滤的数据再过一遍无害。
- **前端** `public/app.js:downloadTodoExcel(range)` 重写,核心三改:
  1. **加 `X-Auth-Token` 头**(用 `getToken()`),401 且非 demo 时自动弹登录框再重试。
  2. 接受 `range` 参数,按 range 算 mon/sun;前端用 `collectTodos(range)` 预过滤 tasks 传给后端,语义与待办页一致。
  3. 文件名按 range 命名;成功后 toast `已导出 <文件名>`。
- **前端** `public/app.js:openExportModal()` 新增导出模态框:`日/周/月` 三选一,每个显示 preview(`X 个任务 · 涉及 Y 个项目`),默认选中本周。确认调 `downloadTodoExcel(kind)`。
- **前端** `public/app.js:buildTodos()` 删掉内嵌的「导出 Excel」按钮(2111 行),改成工具栏右侧**独立功能键** `todoExportBtn`(与「仅逾期/搜索」同级,`margin-left:8px`)。
- **HTML** `public/index.html` 新增 `<div id="exportModal" class="modal hidden">` 空容器,`openExportModal` 注入内容,与其它模态框共用 `.modal-box/.modal-head/.x/.btn/.btn.primary` 样式。
- **CSS** `public/style.css` 末尾追加 `.todo-export` / `.exp-opts` / `.exp-opt` / `.exp-name` / `.exp-meta`,用 `--accent`/`--border`/`--bg-hover` 主题变量,深浅色自动适配。

## 鉴权坑(原 bug 根因)
- **症状**:用户截图「导出失败：未授权：请先登录（X-Auth-Token)」
- **根因**: `public/app.js:downloadTodoExcel()` 直接 `fetch(API + '/reports/todo-export', {...})` **没传 token**;`server.js:587-588` 强制非 GET 请求必须登录 → 401。
- **修复**: fetch 时手动加 `'X-Auth-Token': getToken()`;401 + 非 demo → `showLogin()` 弹登录框,成功后再调一次。
- **同类坑**: 项目内任何 `downloadXxxExcel()` 若用裸 fetch 都可能踩这个;后续所有新导出端点一律 `api()` 或显式带 token。

## 设计要点
- **范围语义**: 与待办页 tab 完全一致(`collectTodos` 单一函数),保证 UI 看到什么、导出去就是什么。
- **预览**: 模态框里实时显示三段各自的任务数/项目数,用户不会"点了才知道没数据"。
- **默认选中本周**: 保持原习惯路径,但视觉上明确告诉用户"我也能导日/月"。

## v1.5.4 续：排版统一 + 「导出 ≠ 页面」内容 bug（2026-09-10）

### 排版对齐计划表
用户先给计划表截图要求深蓝表头/细边框/全列居中，随后要求「我的待办导出的 excel 也参考这个弄一下」。现待办清单与计划表/差异对比完全同观感：表头 `#1F4E78` 白字加粗、四边细黑线、6 列全居中、日期真日期 `yyyy/m/d`；**只保留逾期/顺延状态列红字加粗 `#E0241B`** 作为功能性高亮。旧的矢车菊蓝三色板（`#1F3864`/`B4C7E7`/`F2F7FD`）废弃。

### 顺手修掉「导出内容 ≠ 待办页」
- 症状：待办页标着 `⚠ 逾期` 的任务，导出的 Excel 里一条都没有。
- 根因：后端 `buildTodoXlsx` 二次过滤写成 `dueDate >= monIso`（要求到期日不早于周期首日）——逾期任务恰恰 `dueDate < monIso`，被整批丢掉；连带 `⚠ 逾期` 分支永远不可达。下周待办还缺上界，会把下下周到期的任务也导出。
- 教训：**前端已预过滤的数据，后端"再过一遍"的过滤条件必须逐字对齐前端语义**，否则就是静默的数据丢失（页面与导出不一致，没有任何报错）。这是本篇开头"范围语义：UI 看到什么、导出去就是什么"的具体反例。
- 修复：与 `collectTodos()` 对齐——排除已完成/无截止日期；今日/本周/本月 = 逾期 + 周期内到期；下周 = 顺延无条件纳入 + 到期日落在下周窗口内（含上界）。
- 回归：`test/lib-xlsx-export.test.cjs` 78 → 99 断言，含「逾期任务必须出现在导出里且红字」「下周不得混入下下周」「无截止日期不导出」。
