# 演示版下线与单实例改造

2026-09-11，用户拍板「5180 不再有用途」，把演示版**彻底移除**（而非只停进程）。清理深度：代码全清 + 数据备份后删除。

## 为什么不是「只停 5180」

`--demo` 不只是个端口开关，它是一条**鉴权后门**：带该参数启动即 `authorized() => true`、`req.user` 恒为 admin 视角。留在代码里就意味着任何能以参数启动进程的人都能拿到全量写权限。彻底移除顺带堵掉它。

## 关键设计：`--demo` 必须**退出**而不是忽略

```js
if (process.argv.includes('--demo')) { console.error('...已下线...'); process.exit(1); }
```

静默忽略的后果很严重：`PORT` 默认值已改成 5181，但服务器上遗留的旧 `watchdog.js` 仍按 `{port:5180, args:['--demo']}` 拉起 —— 若忽略参数，它会以「正式版」身份在 5180 起一个进程，**与 5181 双写同一份 `data/app.db`**。直接退出能让问题在日志里立刻暴露。

同理，`PORT` 默认值从 5180 改成 5181：单实例时代默认端口就该是正式版。

## 三个踩坑（都不是外观问题）

1. **批量替换把函数定义也替了 → 自递归**
   把 `req(DEMO, ...)` 全量替换成 `J(...)` 时，`const J = (m,p,b) => req(DEMO, m,p,b, token)` 里的调用也被换掉，成了 `J => J(...)`。测试表现是 `Maximum call stack size exceeded`，套件状态 `PASS=6 FAIL=1`。
   **教训**：全局字符串替换后必须回头读替换点本身，尤其"定义行里含被替换模式"的情况。

2. **离线单文件版可能被 `state.demo` 移除打挂**
   `offline-adapter.js` 原本靠伪造 `/api/readonly` 返回 `{demo:true}` 让前端跳过登录。删掉 `state.demo` 后它有弹登录框出不来的风险。
   核对后确认：离线版实际是**预置 `kb-user` 到 localStorage** 来跳登录的，不依赖 `state.demo`，未受影响。但仍把返回的 `demo` 字段一并改成 `tag:'offline'`，免得留下误导性字段。

3. **冒烟脚本残留变量**
   `_smoke_v2.js` 末尾的判断仍引用已删的 `demoShown`，会 `ReferenceError`。改断言为 `projCount >= 3 && cards > 0 && errors.length === 0`。
