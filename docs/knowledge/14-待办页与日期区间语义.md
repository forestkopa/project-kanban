# 待办页与日期区间语义

## 背景
登录后 `dueReminder()` 弹「待办提醒：逾期 N / 今天到期 M [查看]」，原「查看」按钮强制跳到 `board` 视图且只跳第一个项目（`state.currentId = firstPid`），体验莫名其妙（数字≠跳转、强制改视图）。2026-09-01 决定将周报「待完成项目清单」面板拆出为独立「待办」页（今日/本周/本月），并删掉周报里的该面板。

## 实现位置
- `public/index.html`：新增页签 `<button class="tab" data-view="todos">待办</button>`（点击由 `app.js` 统一的 `$$('.tab')` 绑定自动生效，无需改 JS 绑定）+ `<section id="todos" class="view hidden">`。
- `public/app.js`：
  - `render()`：`secMap`/`globalViews`/隐藏列表加 `todos`；switch 加 `else if (state.view === 'todos') buildTodos();`。
  - `dueReminder()`：「查看」改为 `state.view = 'todos'; render();`（不再跳 board）。
  - `collectTodos(range)`：抽出的取数函数（today/week/month）。
  - `buildTodos()`：三段渲染，复用 `.todo-*` CSS、`weekRange`、`activeProjects`、`ICON.download`。
  - 后端 `/api/reports/todo-export` **不动**；导出入口迁到待办页「本周」段（仍调 `downloadTodoExcel`）。

## 关键设计决策
1. **点击任务 → 弹编辑模态框，不跳看板**
   原投诉是「强制跳看板」。新页每个 `.todo-t` 绑定 `onclick` → `openTaskModal(p, t)`。注意 `openTaskModal`/`saveTask` 依赖 `proj()`（= `state.currentId` 指向的项目），所以点击前先 `state.currentId = pid`，确保编辑下拉与保存 PUT 指向**正确项目**；模态框覆盖在当前待办页之上，关闭后 `render()` 仍在 todos 视图，无强制视图切换。
2. **日期区间语义：用「到期日落在周期内(含逾期)」，不用重叠区间**
   - ⚠️ 坑：原周报面板的筛选是「重叠区间」`(!start || start<=sun) && (!due || due>=mon)`。对**无 startDate** 的任务，`start` 视为 -∞，于是任意「未来到期」任务（如 10-01 到期）都满足 `due>=mon` 被算进「本周」——在独立待办页里会显得离谱（下月任务出现在本周）。
   - 修正：`collectTodos` 改为按**到期日**判断：
     - `today`：`dueDate <= today`（逾期 + 今天到期）
     - `week`：`dueDate <= sunIso`（逾期 + 本周一~周日 内到期）
     - `month`：`dueDate <= moEndIso`（逾期 + 本月内到期）
     - 无 `dueDate` 的任务三段都不显示（无法判定"到期"）。
   - `overdue` 标记 = `dueDate < 周期起点`（today→today；week→monIso；month→moFirstIso），用于排序「逾期优先」与标 ⚠。

## 验证
- `node --check` 通过；`collectTodos` 用 mock 数据跑过：本周只含逾期+本周内到期，下月(10-01)/跨周(09-10/09-15)任务正确不串入；归档项目被 `activeProjects()` 排除。
- 渲染结构与线上周报面板**同构**（复用相同 `.todo-*` 模板），风险低。

## 后续可调
- **任务点击行为（2026-09-01 15:0x 已改为 (b)）**：点任务 → 跳对应项目看板并高亮定位该卡片，而非弹编辑模态框。实现：`buildTodos` 的 `.todo-t` 点击 handler 设 `state.currentId=pid; state._jumpTaskId=tid; state.view='board'; render()`；`renderBoard()` 末尾若 `state._jumpTaskId` 命中 `.card[data-id]` 则 `scrollIntoView({block:'center'})` + 加 `.card-flash`（1.6s 后移除）。**编辑入口仍在看板卡片的铅笔按钮**。
- 若希望「本周/本月」也纳入"本周刚开始、但到期在下月"的任务，需回到重叠区间语义（并接受下月任务串入的副作用）。

## 美观改版（2026-09-01 15:0x）

- 任务行重排：左侧**状态点**（over=红实心 / ms=蓝实心 / 普通=空心）、标题、`工期` 小标签、右侧**到期日胶囊**（逾期变红 + ⚠）、hover 显「看板↗」提示。
- KPI 改成胶囊（`grid-column:1/-1` 横跨整行）。
- 看板高亮动画 `.card-flash`（`outline` + `cardFlash` keyframe 1.6s 淡出）。
- 适配深浅色（全用 `--accent/--danger/--bg-*/--border/--text-*` 变量；逾期红用 `color-mix(in srgb, var(--danger) 14~16%, transparent)`）。

## v1.4.3 优化（项目多场景，2026-09-01）
原设计「今日/本周/本月」三段**各自全量渲染**，项目多时两个痛点：① 同一逾期任务同时出现在三段 → 列表 ×3 冗余；② 所有项目分组全展开、项目内任务无序 → 长列表难浏览、找不到最急的。
优化（用户选 A+B+C，未选 D）：
- **A 去重 + tab 切换**：`buildTodos` 改为顶部「今日/本周/本月」三个 tab，只渲染**当前激活段**（`collectTodos` 只跑一次），任务不再重复。默认段 `state.todoRange='today'`（最聚焦、逾期最显眼）。
- **B 折叠 + 项目内排序**：每个项目分组头可点击折叠，状态持久化到 `localStorage`（`kb-todo-collapse-<range>-<pid>`）；`collectTodos` 内项目任务按 `dueDate` 升序排序（逾期最早最前）。
- **C 过滤/搜索**：顶部过滤栏「仅逾期」开关 + 项目名/任务名搜索框。`collectTodos` 应用 `state.todoFilter`；搜索用 `renderTodoList()` **只局部刷新** `#todoList`，不重建工具栏 → 搜索框光标不丢（关键坑：若整页重渲搜索框会被替换丢焦点）。
- 事件统一用 `wrap` 元素**事件委托**（`onclick/onchange/oninput`），因为 `wrap.innerHTML` 重建不影响委托绑定，避免重复 addEventListener。
- 导出按钮保持「导出本周」，仅在本周 tab 激活时显示，后端 `/api/reports/todo-export` 不动。
