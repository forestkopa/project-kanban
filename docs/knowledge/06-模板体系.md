# 模板体系

## 无 JSON 模板导入

- 已删除 JSON 模板导入：`accept` 仅 `.xlsx`。
- 参考模版 Excel 导入 = 新建模板（取文件名、阶段作展示字段）。

## 模板卡片操作

- 可删除、可改名：`PUT/DELETE /api/templates/:id`。

## 导出参考模版

- 由内置模板生成的**计划表方言 Excel**：`GET /api/templates/reference-xlsx?tplId=`（与计划表导出同构）。
- 列：`序号 / 阶段 / 任务 / 负责人 / 开始日期 / 截止日期 / 工期(天) / 状态 / 备注`；表头置顶、数据从第 2 行起，**无「项目开始」行**。
- **序号 1 的开始日期即项目开始时间**（写固定值、不带公式），其后任务开始 `=WORKDAY.INTL(F<上一行>,1)`、截止 `=WORKDAY.INTL(E<本行>,G<本行>-1)`，逐行级联。
- **阶段列用合并单元格**（阶段名只填首行）。导入侧靠 `curPhase` 沿用当前阶段，不依赖每行都填。
- 样式：表头深蓝 `#173A5A`（「深蓝·深色 25%」）白字加粗、全表细黑边框、全列居中、日期 `yyyy/m/d`。
- ⚠️ **必须用 `xlsx-js-style` 建表与写出**：普通 `xlsx` 不保存 `cell.s`，样式会在落盘时被整体丢弃（曾表现为「导出的 Excel 是白板」）。
- 文件名净化：模板名可能含 `/`（历史内置名「智能摄像头 / AI 视觉」即踩坑来源）会拼出非法文件名，服务端 `Content-Disposition` 与前端下载名都替换为 `_`。守卫保留 —— 用户自建/导入的模板名不受控。
- 回归锁：`test/template-export-import.test.cjs`（样式/合并/文件名/导入闭环 + 源码约束）。

## 内置模板

当前 4 个：智能门锁 / 智能手表 / 智能摄像头 / 智能音箱（「社区共享-智能台灯」已删）。

**命名规范**：模板名只表示产品形态，不带品类后缀。品类归属由项目「产品类型」字段表达（`data/options.json` 可配置）。早期模板名曾兼做品类标注（`智能手表 / 可穿戴`、`智能摄像头 / AI 视觉`、`智能音箱 / 语音助手`），该职责已被产品类型字段取代，2026-09-11 全部清理。

> 文件位置：**正式部署**读项目根 `templates.json`（升级包会带上）；设了 `KB_DATA_DIR` 的**隔离实例**读数据目录下的副本，首次从项目根复制种子 —— 测试里的导入/改名不会写脏仓库文件。
>
> 历史：2026-09-11 前有 demo 版，读独立的 `templates.demo.json`（已随演示版一起删除）。
