# 多用户 · 权限管理设计大纲

> 目标场景：1-10 人小团队（智能硬件 NPI 项目管理），SQLite 数据层已就绪（users/role 字段已建）。
> 本文先参考行业成熟模型，再给出适合本项目体量的轻量权限方案，供决策。

---

## 一、参考的行业优秀案例

| 产品 | 权限模型 | 核心借鉴点 |
|---|---|---|
| **Jira** | 全局权限 + 每项目 Permission Scheme（授权方案）；角色：Administrator / Project Lead / Developer / Viewer | ① 角色与项目授权分离；② 有明确的**只读角色 Viewer** |
| **禅道** | 部门 + 分组 + ACL；权限按"权限分组"批量授权，成员归组 | ① 分组批量授权（人多了不用逐个配）；② 操作级权限点 |
| **飞书 / TAPD** | 成员 / 管理员 / 访客；数据权限按空间、项目维度隔离 | ① 访客 = 只读（给领导/客户看）；② 项目级数据隔离 |
| **GitHub** | 组织角色 + 仓库权限：Owner / Maintain / Write / Triage / Read | ① **四级权限清晰**：Read 只读、Write 写、Admin 管理；② 资源级授权 |

**共性提炼**（四个成熟产品都具备的规律）：
1. **角色分层是标配**：管理 / 编辑 / 只读 三档，几乎家家都有
2. **数据权限两级**：全局可见（admin） vs 资源级授权（项目归属/共享）
3. **只读角色独立存在**（Viewer / Read / 访客）——给领导汇报、给评委演示、给跨部门查看

## 二、本项目推荐模型（轻量三档）

### 2.1 角色

| 角色 | 定位 | 典型使用 |
|---|---|---|
| **admin** 管理员 | 全部权限 | 项目负责人本人：管用户、看全量、出总报告 |
| **member** 成员 | 自己的项目全权 | 团队成员：管自己的项目/任务 |
| **viewer** 访客（V2） | 只读 | 领导、跨部门同事、评委（可看汇总，不能改） |

> V1 先落地 admin / member 两档（当前已实现 role 字段，只差权限判断），viewer 留 V2。

### 2.2 数据可见范围（V1 简单版）

```
admin   → 全部项目（全量列表 + 全量报告）
member  → 仅自己创建的项目（owner = 自己）
V2 增强 → 项目可共享给多个 member 协作（多人共管一个项目）
```

### 2.3 操作权限矩阵

| 操作 | admin | member | viewer(V2) |
|---|:---:|:---:|:---:|
| 创建项目 | ✅ | ✅ | — |
| 编辑自己的项目/任务 | ✅ | ✅ | — |
| 编辑他人项目 | ✅ | 仅被共享的 | — |
| 删除项目 | ✅ | 自己的 | — |
| 查看项目 | 全部 | 自己的 | 被共享的（只读） |
| 用户管理（建用户/改密/禁用） | ✅ | — | — |
| 系统设置（选项/AI/只读开关） | ✅ | — | — |
| 聚合报告 | 全量 | 仅自己的统计 | 汇总页（只读） |
| 导出 xlsx | ✅ | 自己的 | — |

### 2.4 聚合报告权限（对应你的原始需求）

- **admin**：按人聚合全量报告（谁有多少项目、完成率、逾期、阶段分布）
- **member**：只能看自己的统计（个人报告），看不到别人
- **viewer**（V2）：只读的全局汇总页（不暴露个人明细，防泄密）

## 三、分阶段落地路径

| 阶段 | 内容 | 工作量 |
|---|---|---|
| **V1**（本轮） | admin/member 两角色 + owner 私有 + admin 全量 + 个人/全量报告；member 建用户需 admin 批准（现 POST /api/users 已限 admin） | 前端登录 + 用户管理 + 报告页 |
| **V2**（后续） | viewer 只读角色；项目共享协作（share_users 字段）；成员自助改密；用户禁用/启用 | 中 |
| **V3**（远期） | 部门/分组批量授权；操作审计日志（谁改了啥）；项目移交（owner 变更） | 大，可不做 |

---

## 四、待你拍板的 4 个问题

1. **成员之间是否要共享同一个项目**（多人共管）？还是各管各的、互不干扰？
   - 各管各的 → V1 直接做，共享留 V2
2. **要不要 viewer 只读角色**？给领导/跨部门看汇总用（演示版 demo 已覆盖评委场景，viewer 是给内部领导的）
3. **聚合报告成员能否看自己的个人报告**？还是只有 admin 能看报告入口？
4. **要不要成员自助改密码**？（admin 建号时发初始密码，成员自己改）

> 我的默认建议：V1 按「各管各的 + 两角色 + 成员可看自己的报告 + admin 可重置密码」实现，共享与 viewer 留 V2，避免第一版过重。
