# 服务器部署手册（Windows 11 · 拷贝即用）

> 目标：把本机开发好的 kanban project 部署到公司 Windows 11 服务器，公网继续用 `https://kanban.forestkopa.top` 访问。
> 模式：**整个文件夹拷贝过去 → 管理员跑一个脚本 → 服务 + 公网隧道全部就位**。
> 配套：`tools/deploy-server.ps1`（一键部署脚本）；`tools/cloudflared/`（随包携带 cloudflared.exe + 隧道凭据，不入 git）。

---

## 一、拷贝清单（源 = 本机项目文件夹）

| 必须拷贝 | 说明 |
|---|---|
| 整个 `project-kanban/` 文件夹 | 含 `node_modules/`（免服务器联网装包，**绕开 xlsx CDN 源风险**） |
| `data/` | 正式数据 app.db + demo.db + ai.json + auth.token 等 |
| `config.yml` | 隧道配置（脚本会自动改写凭据路径） |
| `tools/nssm-2.24/` | NSSM 服务工具 |
| `tools/cloudflared/` | cloudflared.exe + 隧道凭据 json（**已随包就位，勿删**） |

> ⚠️ 不要只 clone 仓库——`data/`、`config.yml`、`tools/cloudflared/` 都不在 git 里（敏感/体积排除），必须整文件夹拷贝。

---

## 二、服务器三步操作

### 第 1 步：确认环境（服务器上，普通窗口）
```powershell
node -v        # 需 ≥ 22（项目用 node:sqlite）
```
没装：去 https://nodejs.org 装 LTS（≥22）。

### 第 2 步：运行部署脚本（管理员 PowerShell）
```powershell
cd D:\project-kanban            # 改成你拷贝到的实际路径
Set-ExecutionPolicy -Scope Process Bypass -Force   # 临时放开本会话执行策略
.\tools\deploy-server.ps1
```

脚本自动完成：
1. **环境检查**：server.js / node_modules / nssm / node 版本
2. **数据备份**：`data/` → `data-backup-时间戳/`（回滚点）
3. **隧道凭据迁移**：把 `tools/cloudflared/` 的凭据 json 拷到服务器 `%USERPROFILE%\.cloudflared\`，并把 `config.yml` 的 `credentials-file` 重写为服务器路径
4. **NSSM 注册服务** `kanban-watchdog`（幂等：先移除旧的再装；注入 `CLOUDFLARED_PATH` 环境变量指向随包 cloudflared.exe）
5. **启动 + 验证**：本地 5180/5181 探活，等 12s 后探公网 `https://kanban.forestkopa.top`
6. 打印日志路径与**回滚命令**

### 第 3 步：浏览器验证
- 本机：`http://127.0.0.1:5181`（正式版，需登录）
- 公网：`https://kanban.forestkopa.top`（演示版，指向 5180）
- 登录 admin / 初始密码 → 新建项目 → 导出 xlsx → 确认数据与旧库一致

## 三、服务器常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 脚本报"execution policy" | PS 执行策略拦截 | 用第 2 步的 `Set-ExecutionPolicy -Scope Process Bypass` |
| 公网打不开，本地正常 | 隧道未就绪 / 凭据缺失 | 看脚本输出是否有 `cloudflared NOT found` 警告；检查服务器能出公网（443/7844） |
| `nssm` 拒绝访问 | 未用管理员运行 | 右键 PowerShell → 以管理员身份运行 |
| 5181 登录后操作 500 | 数据目录权限 | 给服务账号 `data/` 读写权限 |
| 端口被占用 | 旧实例残留 | `nssm remove kanban-watchdog confirm` 后重跑脚本 |

## 四、回滚（万一出问题）

```powershell
# 停服务
& "D:\project-kanban\tools\nssm-2.24\win64\nssm.exe" stop kanban-watchdog
# 还原数据（从部署时备份）
xcopy "D:\project-kanban\data-backup-<时间戳>\*" "D:\project-kanban\data\" /E /Y
# 重启服务
& "D:\project-kanban\tools\nssm-2.24\win64\nssm.exe" start kanban-watchdog
```
> 本机开发环境不受影响，随时可继续用。

## 五、日常运维（服务器上）

| 操作 | 命令 |
|---|---|
| 看服务状态 | `& "D:\project-kanban\tools\nssm-2.24\win64\nssm.exe" status kanban-watchdog` |
| 看日志 | `Get-Content D:\project-kanban\data\watchdog-service.log -Tail 50` |
| 更新代码 | 拷新 `server.js/db.js/public/` 覆盖 → watchdog 检测 mtime **≤15s 自动重启**，无需手动 |
| 重启服务 | `& "...\nssm.exe" restart kanban-watchdog`（改 watchdog.js 自身才需要） |
