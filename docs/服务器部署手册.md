# 服务器部署手册（Windows 11 · 拷贝即用）

> 目标：把本机开发好的 kanban project 部署到公司 Windows 11 服务器，公网继续用 `https://kanban.forestkopa.top` 访问。
> 模式：**整个文件夹拷贝过去 → 管理员跑一个脚本 → 服务 + 公网隧道全部就位**。
> 配套：`tools/deploy-server.ps1`（一键部署脚本）；`tools/cloudflared/`（随包携带 cloudflared.exe + 隧道凭据，不入 git）。

---

## 一、拷贝清单（源 = 本机项目文件夹）

| 必须拷贝 | 说明 |
|---|---|
| 整个 `project-kanban/` 文件夹 | 含 `node_modules/`（免服务器联网装包，**绕开 xlsx CDN 源风险**） |
| `data/` | 正式数据 app.db + demo.db + ai.json + auth.token 等 |
| `config.yml` | 隧道配置（脚本会自动改写凭据路径） |
| `tools/nssm-2.24/` | NSSM 服务工具 |
| `tools/cloudflared/` | cloudflared.exe + 隧道凭据 json（**已随包就位，勿删**） |

> ⚠️ 不要只 clone 仓库——`data/`、`config.yml`、`tools/cloudflared/` 都不在 git 里（敏感/体积排除），必须整文件夹拷贝。

---

## 〇、服务器前置依赖（提前准备）

| 依赖 | 用途 | 说明 |
|---|---|---|
| **Node.js ≥22** | 运行 server/watchdog | **唯一必须提前装的**（winget / 官网） |
| **PowerShell 执行策略** | 放行 .ps1 / npm | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`（输入 `Y` 确认） |
| **管理员权限** | NSSM 注册服务 | 运行脚本时"以管理员身份运行" |
| cloudflared.exe + 凭据 | 公网隧道 | ✅ 已随包 `tools/cloudflared/`，不用装 |
| NSSM | 服务守护 | ✅ 已随包 `tools/nssm-2.24/`，不用装 |
| node_modules（含 xlsx） | 项目依赖 | ✅ 随文件夹拷贝，**不用 npm install**（绕开 xlsx CDN 源） |

**企业网络注意**：服务器需能**出站** 443 + 7844（Cloudflare 隧道）+ 53（DNS）；Cloudflare Tunnel 是出站连接，**无需开放入站端口**。防火墙/杀软若拦 cloudflared.exe 需放行。

## 二、服务器三步操作

### 第 1 步：确认环境（服务器上，普通窗口）
```powershell
node -v        # 需 ≥ 22（项目用 node:sqlite）
```
没装：去 https://nodejs.org 装 LTS（≥22），**或 winget 一键装**（Win11 自带包管理器）：
```powershell
winget install --id=OpenJS.NodeJS.LTS -e --source winget
# 装完【关闭当前 PowerShell 重开】再验证（PATH 只对新窗口生效）：
node -v
npm -v
```

> ⚠️ 若 `npm` 报 **"禁止运行脚本"**（npm.ps1 被执行策略拦截）→ 执行第 2 步的 `Set-ExecutionPolicy`，或直接改用 `npm.cmd -v`。

### 第 2 步：运行部署脚本（管理员 PowerShell）
```powershell
cd D:\project-kanban            # 改成你拷贝到的实际路径
Set-ExecutionPolicy -Scope Process Bypass -Force   # 临时放开本会话执行策略
.\tools\deploy-server.ps1
```

> 💡 **执行策略两种处理**：
> - 临时（推荐，只对当前窗口）：上面第 2 行
> - 永久（当前用户）：`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`（需输入 `Y` 确认）——若 `npm` 报"禁止运行脚本"就是这个没设

脚本自动完成：
1. **环境检查**：server.js / node_modules / nssm / node 版本
2. **数据备份**：`data/` → `data-backup-时间戳/`（回滚点）
3. **隧道凭据迁移**：把 `tools/cloudflared/` 的凭据 json 拷到服务器 `%USERPROFILE%\.cloudflared\`，并把 `config.yml` 的 `credentials-file` 重写为服务器路径
4. **NSSM 注册服务** `kanban-watchdog`（幂等：先移除旧的再装；注入 `CLOUDFLARED_PATH` 环境变量指向随包 cloudflared.exe）
5. **启动 + 验证**：本地 5180/5181 探活，等 12s 后探公网 `https://kanban.forestkopa.top`
6. 打印日志路径与**回滚命令**

### 第 3 步：浏览器验证
- 本机：`http://127.0.0.1:5181`（正式版，需登录）
- 公网：`https://kanban.forestkopa.top`（演示版，指向 5180）
- 登录 admin / 初始密码 → 新建项目 → 导出 xlsx → 确认数据与旧库一致

## 三、服务器常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 脚本报"execution policy" | PS 执行策略拦截 | 用第 2 步的 `Set-ExecutionPolicy -Scope Process Bypass` |
| 公网打不开，本地正常 | 隧道未就绪 / 凭据缺失 | 看脚本输出是否有 `cloudflared NOT found` 警告；检查服务器能出公网（443/7844） |
| `nssm` 拒绝访问 | 未用管理员运行 | 右键 PowerShell → 以管理员身份运行 |
| 5181 登录后操作 500 | 数据目录权限 | 给服务账号 `data/` 读写权限 |
| 端口被占用 | 旧实例残留 | `nssm remove kanban-watchdog confirm` 后重跑脚本 |
| 公网验证报 TLS/握手失败 | PS 5.1 默认 TLS 过旧 | 脚本已内置 TLS 1.2 强制（`[Net.ServicePointManager]::SecurityProtocol`），无需手动 |
| `node` 命令找不到 | 未装 Node 或 PATH 未刷新 | 装 Node 后【关闭 PowerShell 重开】；或用绝对路径 `& "C:\Program Files\nodejs\node.exe" -v` |

## 四、回滚（万一出问题）

```powershell
# 停服务
& "D:\project-kanban\tools\nssm-2.24\win64\nssm.exe" stop kanban-watchdog
# 还原数据（从部署时备份）
xcopy "D:\project-kanban\data-backup-<时间戳>\*" "D:\project-kanban\data\" /E /Y
# 重启服务
& "D:\project-kanban\tools\nssm-2.24\win64\nssm.exe" start kanban-watchdog
```
> 本机开发环境不受影响，随时可继续用。

## 六、版本更新（数据库安全机制）

> **核心原则：`data/`（数据库 + AI Key + token）永远在服务器上，更新包永不包含它。**

### 双包机制

| 包 | 内容 | 用途 |
|---|---|---|
| `project-kanban-deploy.zip` | 全部代码 + **data/**（含 app.db 初版） | 🆕 **仅首次部署** |
| `project-kanban-update.zip` | 全部代码，**不含 data/** | 🔄 **所有后续版本更新** |

### 更新流程（3 步）

```powershell
# 1. 备份服务器数据（保险，可回滚）
Copy-Item -Recurse D:\project-kanban\data D:\project-kanban\data-backup-$(Get-Date -Format yyyyMMdd-HHmmss)
# 2. 用 project-kanban-update.zip 解压覆盖（全部选"是"；包内无 data/ → 服务器数据自动保留）
#    （解压目标 D:\project-kanban\，覆盖现有代码文件）
# 3. 自动生效：watchdog 检测代码 mtime → ≤15s 自动重启，无需手动操作
```

### 数据库兼容性

- `db.js` 启动**幂等建表**（`CREATE TABLE IF NOT EXISTS`）+ 内置迁移（`migrateJson`/`ensureAdminAndMigrate`）——新版本启动自动适配旧库，用户/项目/任务数据全保留。
- 若未来大版本改 schema，会在发布说明标注"需备份后升级"；常规小版本全部无缝。
- **红线**：已运行的服务器永远不要用 `deploy.zip`（含 data/）覆盖——只允许 update.zip。
