# 一键升级排障手册（v1.5.5）

> 适用症状：**点「一键升级」提示完成（或任务结束），刷新后版本仍是旧的**；或升级期间页面长时间卡住、公网不可达。
> 结论：v1.5.1 修的是「watchdog 热重载与升级流程打架导致的静默中断」；v1.5.5 修的是「解压同步阻塞导致服务假死数分钟」。
>
> **v1.5.5 新增（2026-09-10）**：升级期间页面长时间卡「服务重启中…」、公网持续 502 的问题已定位并修复。
> 根因是 **解压用 `spawnSync` 冻结了整个事件循环**（实测 97 秒端口 100% 无响应），
> 叠加 **升级包里塞了 1047 个 node_modules 文件**（解压占整个升级 86% 的时间）。
> 修复后同一等价环境复验：解压 97s → **9.1s**、端口不可达 37s → **1s**、总耗时 118s → **24.3s**。
>
> **怎么判断"真挂了"还是"只是慢"：看版本号，别看感觉。**
> `curl.exe -s https://kanban.forestkopa.top/api/version` 能返回且版本已是新的 → 升级其实成功了。
> 前端提示超时（120s）≠ 失败；`logs/upgrade-YYYY-MM-DD.log` 里 `extract done` / `verify ok` / `restart:` 三行齐了就是链路走完。

## 0. 一分钟定性（先跑这三条）

```powershell
cd C:\Users\Administrator\Desktop\project-kanban-deploy

# ① 版本号（唯一可信的成功判据）
curl.exe -s https://kanban.forestkopa.top/api/version

# ② 升级日志尾部（有没有 extract done / verify ok / restart:）
Get-Content (Get-ChildItem logs\upgrade-*.log | Sort LastWriteTime -Desc | Select -First 1).FullName -Tail 30

# ③ 现场残留（失败包会改名保留，便于事后分析）
Get-ChildItem upgrade-tmp-*.zip, upgrade-failed-*.zip -ErrorAction SilentlyContinue
Get-ChildItem -Directory data-backup-upgrade-* | Sort LastWriteTime -Desc | Select -First 3
```

## 1. 根因（为什么会"提示完成但版本没变"）

升级的后台任务跑在 `server.js` 进程里，流程是：下载 → 备份 → `Expand-Archive` 解压覆盖 → 重启。

而 `watchdog.js` 每 15 秒做一次代码热重载：扫描 `server.js / db.js / lib / public` 的 mtime，一旦变新就 `taskkill` 掉当前 server 进程并重新拉起。

两者叠加后的时间线：

| 时刻 | 事件 |
|------|------|
| T+0 | 开始解压，逐文件覆盖 `server.js`、`public/*`、`lib/*` |
| T+≤15s | watchdog 探测到 mtime 变新 → 判定"代码更新" → **杀掉正在执行升级的 server 进程** |
| T+≤15s | 解压中断（只覆盖了一部分文件，甚至一个都没覆盖完） |
| T+≤30s | watchdog 用（残缺的）新代码拉起 server；**任务状态只存在内存，随进程一起丢失** |
| 前端 | 轮询 `/api/admin/upgrade/status` 得到"任务不存在/已结束" → 显示"任务结束/完成" |
| 实际 | 代码没换 → `/api/version` 仍是旧版本号 |

诊断佐证（2026-09-09 公网实测）：服务器 `/api/version` = `1.4.7-hotfix5`，`/app.js` = 154,334 字节（旧版），而新版 app.js 是 170,306 字节 → **一个文件都没被覆盖**。

此前还有一个放大问题排查难度的因素：watchdog 以 `stdio:'ignore'` 拉起 server，**升级过程没有任何日志**，失败了也无从查起。

## 2. v1.5.1 的修复

| # | 修复 | 位置 |
|---|------|------|
| 1 | **升级锁** `data/upgrade.lock`：解压期间 watchdog 跳过热重载（端口挂了仍拉起，自愈不失效）；成功/失败都强制解锁 | `watchdog.js` / `lib/upgrade.js` |
| 2 | **解压后强制校验** `package.json` 版本号是否等于目标版本，不符直接判 `error` 并提示改用离线升级（不再静默"完成"） | `lib/upgrade.js` |
| 3 | **任务状态持久化** `data/upgrade-task.json`：进程被重启后前端仍能拉到 `done`，不再显示"任务不存在" | `lib/upgrade.js` |
| 4 | 解压优先用系统内置 `tar.exe`（bsdtar，无 260 字符路径限制），失败回退 `Expand-Archive`；下载超时 180s → 600s 并重试 3 次 | `lib/upgrade.js` |
| 5 | **全过程写日志** `logs/upgrade-YYYY-MM-DD.log` | `lib/upgrade.js` |
| 6 | 前端：重启期间请求失败显示"服务重启中…（N s）"并持续等待最多 120s，不再静默 | `public/app.js` |
| 7 | 离线升级脚本同样加锁（避免覆盖到一半被重载成"半新半旧"），并打印解压后版本号 | `tools/local-upgrade.ps1` |

回归测试：`test/watchdog-upgrade-lock.test.cjs`（3 场景）+ `test/upgrade.integration.test.cjs` 扩展（版本未变必判 error / 持久化跨重启可读 / 结束必解锁 / 日志落盘）。全套 28 套件通过。

## 3. 本次如何把服务器升上来（一次性，走离线）

> 在线升级修的是"代码"，可服务器现在跑的就是有 bug 的旧代码 —— 鸡生蛋。所以**这一次必须用离线脚本**，升到 v1.5.1 之后，在线一键升级才恢复。

1. 拿到 `project-kanban-update.zip`（v1.5.1，22.4MB）：
   - GitHub Release 页下载，或从开发机 `C:\Users\Administrator\Downloads\kanban\` 拷贝（U 盘 / 内网均可）。
2. 拷到服务器任意目录，例如 `D:\upgrade\project-kanban-update.zip`。
3. 在服务器上**以管理员身份**打开 PowerShell，cd 到看板项目根目录，执行：

```powershell
powershell -ExecutionPolicy Bypass -File tools\local-upgrade.ps1 -Zip "D:\upgrade\project-kanban-update.zip"
```

4. 脚本输出关注三行：`已加升级锁` → `解压后版本: v1.5.1` → `重启: 成功`。
   - 若提示"服务重启失败（多半未以管理员身份运行）"，右键 PowerShell 用管理员重跑，或手动 `Restart-Service kanban-watchdog -Force`。
5. 浏览器 **Ctrl+F5** 硬刷新，侧栏底部版本号应为 `v1.5.1`。公网 `https://kanban.forestkopa.top/api/version` 也应返回 `1.5.1`。

**回滚**：脚本备份在 `data-backup-upgrade-<时间戳>\`，需要时用该目录覆盖回 `data\`。

## 4. 以后怎么在线升级（修好之后）

侧栏「版本」→ 点「一键升级」→ 确认。流程全自动：下载 update.zip → 备份 → 解压覆盖 → 重启。

进度条阶段：下载（0-70%）→ 备份（70-85%）→ 解压（85-95%）→ 校验（95-98%）→ 完成并重启。

- 重启期间公网会中断约 10-30 秒，页面显示"服务重启中…（N s）请稍候"，属正常，不要关页面。
- 若失败，页面会给出明确中文原因；详细过程查 `logs\upgrade-YYYY-MM-DD.log`。
- 若公司宽带到 GitHub 下载慢，可在服务器设环境变量 `KANBAN_UPGRADE_ASSET_URL` 指向本地 zip 绝对路径（重启服务生效），绕开 CDN。

## 5. 快速自检命令（服务器端，PowerShell）

```powershell
# 当前版本
(Get-Content package.json -Raw | ConvertFrom-Json).version
# 服务状态
Get-Service kanban-watchdog
# 是否有残留升级锁（正常应不存在）
Test-Path data\upgrade.lock
# 最近升级日志
Get-Content (Get-ChildItem logs\upgrade-*.log | Sort-Object Name | Select-Object -Last 1).FullName -Tail 40
```
